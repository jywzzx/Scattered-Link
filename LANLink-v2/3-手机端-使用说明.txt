手机端使用说明
================================================================

一、手机端与电脑端可以互联
----------------------------------------------------------------

可以。手机端与电脑端使用同一套虚拟局域网协议，配置正确后
双方被分配到同一虚拟局域网中，可直接使用对方的虚拟 IP。

本说明依据手机端实际界面编写，各项名称与界面一致。

二、为什么必须用「导入配置文件」而不能只填一个地址
----------------------------------------------------------------

程序生成的配置文件里包含三条连接路径，缺一不可：

  一、局域网地址　　如 tcp://192.168.100.101:41273
     手机与电脑接同一路由器时走这条，完全不经过 NAT，延迟最低。
  二、公网地址　　　如 tcp://113.133.208.7:41273
     异地网络时走这条，需要路由器已开放端口。
  三、公共节点　　　若干条，程序自动探测并写入
     前两条都不通时的中继通道，免注册、免费。

只填公网地址时，若路由器未开放端口，连接会一直超时；
手机端事件日志中会出现大量 connect timeout，即为此因。

三、电脑端提供的配置项
----------------------------------------------------------------

在电脑端点击「① 创建房间」后，界面下方「手机端配置」区域会显示：

  模式：直连优先 / 强制统一中继
  房间密钥：k7m2q9x3rt5vb6n（16 位）
  初始节点：tcp://<电脑公网 IP>:<房间端口>
  局域网地址：<电脑局域网 IP>:<房间端口>
  本机 IPv4：10.144.0.9/24
  房间端口为电脑端本次随机选取的端口，务必以房主界面显示的数值为准

区域下方还会逐条列出「核对项」，那些是导入后必须满足的条件
（取消 DHCP、第二台手机改号、中继模式下节点必须一致等）。
注意：配置文件里没有任何注释，因为导入时没人会打开文件看 ——
所有提示都只出现在电脑端界面上，请照着界面核对。

并提供三种传递方式：

  ★ 二维码　　　　　最快。手机一扫就能拿到完整配置文本
  复制配置内容　　　复制一段带操作说明的完整文本，可用微信发送
  保存为文件　　　　在电脑桌面生成纯 lanlink-phone.toml
  「展开配置正文」　可查看二维码里装的全部文字

四、推荐方式一：扫描二维码（最快）
----------------------------------------------------------------

手机端（EasyTier 官方 App）没有「扫码导入」，也没有「从剪贴板导入」，
只有「导入配置文件」一个入口。所以必须先把文本变成手机上的文件，
这一步无法省略。具体做法：

  一、在电脑端点二维码可看大图，用手机相机或任意扫码 App 扫描
  二、扫描结果是一段文字，全选复制
  三、打开手机「记事本」，新建备忘录，把内容粘贴进去
  四、保存时文件名填 lanlink.toml（后缀必须是 .toml）
  五、在 EasyTier 中点击「导入配置文件」，选择刚保存的文件

五、推荐方式二：微信转发文本
----------------------------------------------------------------

  一、电脑端点「复制配置内容」
  二、粘贴到微信，发给手机（文件传输助手或好友均可）
  三、手机上长按这条消息复制，按上一节第三步起继续操作

六、推荐方式三：导入配置文件（旧方式，仍可用）
----------------------------------------------------------------

一、点击电脑端的「保存为文件」

二、将桌面上生成的 lanlink-phone.toml 发送至手机
   （微信文件传输助手、QQ、数据线均可）

三、在手机端点击顶部工具栏的「导入配置」，选择该文件

四、导入后检查「虚拟 IPv4 地址」处的 DHCP 复选框是否已取消勾选。
   若仍处于勾选状态，请手动取消，并确认地址栏内容为 10.144.0.9/24

五、点击「保存配置」，然后启动该网络

以上三种方式得到的是同一份配置，任选其一即可。
此方式可避免手工输入错误，为推荐路径。

七、手工填写方式
----------------------------------------------------------------

若不使用配置文件导入，请在手机端「基础设置」区域按下列要求填写：

┌──────────────┬────────────────────────────┬──────────────────────┐
│ 界面项        │ 填写内容                    │ 英文界面对照          │
├──────────────┼────────────────────────────┼──────────────────────┤
│ 虚拟 IPv4 地址 │ 10.144.0.9/24              │ IPv4 / Virtual IPv4  │
│               │ 并取消勾选 DHCP            │ 取消勾选 DHCP        │
├──────────────┼────────────────────────────┼──────────────────────┤
│ 网络名称      │ lanlink                    │ Network Name         │
├──────────────┼────────────────────────────┼──────────────────────┤
│ 房间密钥      │ 16 位密钥                   │ Network Secret       │
├──────────────┼────────────────────────────┼──────────────────────┤
│ 初始节点      │ 点击「+ 添加初始节点」后    │ Initial Peers        │
│              │ 填入 tcp://<电脑公网IP>:<房间端口>│ Add Initial Peer     │
│              │ 建议再添加一条 udp:// 同样地址│                      │
│              │ 再添加局域网地址 tcp:// 与 udp://│                   │
├──────────────┼────────────────────────────┼──────────────────────┤
│ 端口转发      │ 留空，不填写任何内容        │ Port Forward         │
└──────────────┴────────────────────────────┴──────────────────────┘

关于「端口转发」：
  该功能的用途是将本机端口映射到虚拟网络内的远端端口，
  格式为 协议://本地地址:本地端口/远端地址:远端端口。
  本方案不需要端口转发，此处必须留空。
  在此处填写地址会导致内核尝试绑定该地址，
  并因该地址不属于本机网卡而报错：
      tunnel error io error: Cannot assign requested address (os error 99)

关于 DHCP：
  DHCP 会使内核自动分配 10.0.0.0/24 网段的地址，
  与电脑端的 10.144.0.0/24 不属同一网段，两端将无法直接通信。
  因此手机端必须取消勾选 DHCP，并使用与电脑端一致的网段。

关于「初始节点」：
  即电脑端的地址。电脑端监听 TCP 与 UDP 的房间端口（每次建房随机选取），
  建议两条均添加，连接成功率更高。
  异地使用时还应添加电脑端的局域网地址与公共节点地址，
  以便在其中一条不通时自动改走另一条。

八、手机热点、校园网、运营商大内网（CGNAT）环境
----------------------------------------------------------------

什么是 CGNAT：
  运营商为节省公网地址，会让许多用户共用一个公网 IP，并在机房
  再做一层地址转换，这就是 CGNAT（运营商级 NAT）。手机流量、
  部分宽带、校园网通常都处在这层之后。
  在这种网络里，你的设备可以主动访问别人，但别人无法主动访问你，
  因此点对点直连（打洞）必然失败。

如何判断：
  电脑端建房后提示「当前为对称型 NAT 且路由器未开放端口」，
  或成员都显示在线、游戏连接却超时，即为这种情况。

解决办法：改用「强制统一中继」
  一、电脑端勾选「强制统一中继」，点击「填入推荐节点」，
      程序会自动填入一个当前可用的公共节点地址。
  二、把该地址告知对方：三台设备必须填完全相同的地址。
      公共节点彼此独立，各自连不同节点时彼此之间没有数据通路，
      表现就是「都显示在线，但互相连不上」。
  三、重新保存并发送手机端配置文件。此时文件内已包含
      disable_p2p、disable_udp_hole_punching、
      disable_tcp_hole_punching 三项，且只保留该节点。
  四、手机端重新导入并启动。

  结论：出口是 CGNAT 不影响互通。只要三台设备挂在同一个公共节点上，
  中继节点就是三方共同的上游，数据由它转发，
  不需要任何人能被对方主动连入。

九、启动与验证
----------------------------------------------------------------

一、启动该网络。系统将请求 VPN 权限，请选择「允许」

二、启动成功后，手机端成员列表中应出现 10.144.0.1（即电脑端）

三、若手机端显示「运行中」但成员列表只有本机，说明尚未连通。
   此时请在手机端打开「显示事件日志」，查看具体报错：
     · connect timeout
       表示所有初始节点均不可达。多数情况是公网地址未开放端口，
       而配置中又缺少局域网地址或公共节点。
       请改用「导入配置文件」方式重新导入。
     · 连接成功但成员列表无 10.144.0.1
       表示网络名称或房间密钥与电脑端不一致，
       请重新导入配置文件。

四、连通性验证方式（任选其一）：
  · 在手机浏览器中访问 http://10.144.0.1
    若电脑端运行了 HTTP 服务，此处应能正常打开
  · 由电脑端点击「测试连通性」，
    程序对该成员执行 ICMP 探测，显示「连通性验证通过」即链路已建立

十、注意事项
----------------------------------------------------------------

一、电脑端与手机端须同时在线。电脑端关闭后，手机端将提示连接中断

二、手机本机虚拟 IP 不得与电脑端（10.144.0.1）或其他成员重复。
   电脑端会自动避开已占用的地址并在界面中显示

三、部分手机系统对后台应用有严格限制。请将本程序加入「允许后台运行」
   或「自启动」白名单，否则锁屏后连接会被系统切断

四、若始终无法接入，请确认：
   · 是否使用了「导入配置文件」方式
   · 手机端 DHCP 是否已取消勾选
   · 双方是否运行了系统级 VPN 或代理软件（会改变路由）

五、关于游戏的局域网房间自动发现：
   该功能依赖操作系统层面的广播转发，Android 与 Windows 的实现差异较大，
   无法保证可用。建议在游戏中直接填写对方的虚拟 IP 地址接入。

十一、技术信息
----------------------------------------------------------------
  协议内核：EasyTier v2.6.4（Apache-2.0）
  网络名称：lanlink（固定值）
  房间密钥：16 位随机字符，房间之间相互隔离
  虚拟网段：10.144.0.0/24
  传输方式：点对点直连，失败时自动转为中继
  加密方式：AES-GCM（内核默认启用）
  本机副本仅负责配置分发，核心功能由上游开源项目提供
