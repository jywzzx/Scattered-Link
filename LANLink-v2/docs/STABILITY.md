# 目标对齐：功能要求 / 稳定性改进 / 实现思路

目标：**类 Radmin VPN、但更稳**——不同网络的设备进同一个虚拟局域网，
能互相看到对方虚拟 IP，游戏里手填 IP 就能连。
明确边界：**不追求"游戏列表自动出现房间"，只要求界面把 IP 显示对。**

---

## 1. 功能要求拆解（对照当前实现）

| # | 要求 | 现状 | 还差什么 |
|---|---|---|---|
| F1 | 任意网络下加入同一虚拟局域网 | ✅ EasyTier P2P（TCP/UDP 双通道 + 对称型打洞 + 中继兜底） | — |
| F2 | 彼此能看到对方虚拟 IP | ✅ 成员列表每 2s 刷新，显示 `IP / 电脑名 / 直连或中继 / 延迟` | 加"一键复制 IP"、IP 冲突处理 |
| F3 | 游戏里手填 IP 能连 | ✅ 虚拟网段 `10.144.0.0/24`，路由由 TUN 交给系统 | 需要提示"游戏服务要监听 0.0.0.0" |
| F4 | 界面能正确显示成员 IP | ✅ 已用 `easytier-cli -o json peer` 拿到结构化数据 | 成员多时的滚动/折叠 |
| F5 | 无人值守稳定运行 | ⚠️ 缺自愈 | 见第 2 节 |

---

## 2. 稳定性改进点（按性价比排序）

### P0 — 会直接导致"用不了"

**S1. 虚拟 IP 冲突**
现在加入者随机取 `10.144.0.2~254`，两个朋友撞号就有一个连不上。
改法：`后缀 = (sha256(密码 + 本机主机名) % 250) + 2`，天然避开；启动后若发现冲突再 `+1` 重试。
好处：同一台机器重连 IP 不变，用户记住的 IP 一直有效。

**S2. 内核进程死了没人管**
现在只在界面上变红字，隧道已经断了但用户还在等。
改法：加 watchdog，每 5 秒检查一次进程存活；掉了就带原参数重启（最多 3 次，指数退避），
并在界面上明确显示"正在重连（第 2 次）"。

**S3. TUN 创建失败没有可读解释**
最常见的三种：没管理员权限 / 杀软删了 `wintun.dll` / 驱动装不上。
改法：启动前预检（是否管理员、`wintun.dll` 是否存在、`%TEMP%\easytier*.log` 有无 ERROR），
失败时直接弹人话："虚拟网卡驱动被拦截，请把 LANLink 文件夹加入杀软白名单"。

### P1 — 会明显影响体验

**S4. 端口被占用**
`11010`（房主）/ `11020`（加入者）是硬编码的。被占就整个起不来。
改法：启动前 `bind` 探测，占用则顺延到下一个空闲端口，并把实际端口写进邀请码。

**S5. 成员列表轮询太重**
每 2 秒起一个 9.5MB 的 `easytier-cli.exe` 进程，笔记本上费电也费 CPU。
改法：降到 3 秒；窗口最小化时暂停；连续 3 次结果不变就退避到 6 秒。

**S6. 防火墙没放行**
Windows 首次会弹窗，用户点"取消"之后就永远连不上。
改法：提权后自动加两条入站规则（只针对本程序 + 私有网络），退出时可选清理。

### P2 — 长期可靠性

**S7. 断线原因可解释**
EasyTier 日志里能区分"打洞失败转中继""对端离线""密钥不匹配"，
现在全塞进日志文本。改法：映射成用户能懂的一句话，显示在状态栏。

**S8. 多网卡/多默认路由**
笔记本同时连 WiFi + 网线 + VPN 时，虚拟网卡的路由可能被抢。
改法：探测并提示"检测到多个默认路由，建议临时断开其他 VPN"。

## 3. 实现思路

### 3.1 架构不变：内核不动，壳层变厚

```
┌─────────────────────────────────────────┐
│ LANLink.exe（我们的壳）                  │
│  · 成员列表（JSON）      ← F2/F4 已实现  │
│  · 健康检查 watchdog     ← S2 待做       │
│  · 预检 + 人话报错       ← S3 待做       │
│  · 端口探测              ← S4 待做       │
└──────────────┬──────────────────────────┘
               │ 子进程，零代码修改
┌──────────────▼──────────────────────────┐
│ easytier-core.exe（Apache-2.0 原版）     │
│  P2P 打洞 · AES-GCM · TUN · 中继         │
└─────────────────────────────────────────┘
```

理由：打洞、NAT 类型识别、对称型生日攻击、中继选路，这四件事上游已经做了几年，
自己重写只会更差。稳定性的增量应该花在**壳层的可观测性、自愈、错误翻译**上，
而不是重写网络层。

### 3.2 成员列表的数据通路（已落地）

```
easytier-cli -p 127.0.0.1:<随机端口> -o json peer
        │  [{ipv4, hostname, cost, lat_ms, loss_rate, tunnel_proto, nat_type}]
        ▼
Engine.parsePeers()  → 过滤掉 cost=Local（自己）
        ▼
AppFrame.renderMembers()  → "10.144.0.2  lanlink-PC  直连  0.44ms"
```

关键细节：**每个实例用随机 RPC 端口**（不是固定的 15888），
否则同机多实例/别的 EasyTier 会把数据串过来 —— 这个坑已经踩过并修了。

### 3.3 为什么不改用二层（TAP）

Radmin 是二层，所以它的"局域网发现"最自然。但：

- Android 的 `VpnService` 只提供 **TUN**，二层在非 root 手机上做不了；
- Windows 二层需要 TAP-Windows 驱动，分发和签名成本都高。

结论：**接受三层**，用"手填虚拟 IP"补偿。这也是本项目的明确取舍，
凡是声称"手机也能二层"的方案，在非 root 设备上都要打问号。

---

## 4. 优先级建议

如果只做三件事，做 **S2（watchdog）+ S3（人话报错）+ S1（IP 不冲突）**。
这三件覆盖了用户实际会遇到的 80% "为什么连不上"。
