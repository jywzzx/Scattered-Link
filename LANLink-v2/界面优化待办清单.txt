[x] P0 **改模式/改中继节点只改了手机配置，电脑端内核不跟着变**（2.6.3）
        —— 实测证据：建房时未勾强制中继 → 内核传参无 disable-*、挂 3 个公共节点；

        PhoneProfile.divergenceHint() 比对「界面声称」与「内核实际」，

[ ] P0 内核运行时修改任何影响启动参数的控件（公共节点复选框、中继框、监听端口），

三、结构性问题（要改动架构，单独排期）
-----------------------------------------------------
[ ] P0 **手机无法被分配唯一地址**：一份 TOML 发给 N 台手机，ipv4 都是 10.144.0.9。
        根治方案：为每台手机生成独立配置（界面上「加一台手机」按钮，点一次生成一份，
        序号自增），或改用内核的 DHCP 模式（实测手机端 DHCP 需服务端支持，尚未验证）。
        现状靠界面提示，属于「能通但需要用户配合」。
[ ] P1 手机端「文本 → 文件」这一步无法绕过：EasyTier 官方 GUI 没有剪贴板导入。
        可选路径：自研一个极简 Android 壳（只做扫码 → 落盘 → 调起 EasyTier），成本高。
        现状：二维码 + 明确的「存为 lanlink.toml」三步说明，已是免费方案下的最优解。
[ ] P1 手机端日志渲染错乱（每条日志一行变成一列字）是 EasyTier GUI 自身缺陷，
        我们无法从本仓库修复；只能减少喂给它的超长无空格字符串。
[ ] P2 没有「房间历史」：每次建房都是新密钥，老朋友要重新收邀请码。
        可做「重建上次房间」（复用密钥，风险是旧邀请码永久有效）。

五、已确认「不需要处理」的现象（记录以免重复排查）
-----------------------------------------------------
[·] 连接超时 ≠ 域名失效。已逐个解析 6 个公共节点，全部正常返回 A 记录；
        失败原因是 UDP/TCP 打洞被 NAT（对称型 / CGNAT）拦掉，与 DNS 无关。
[·] 因此「打洞失败」本身无需处理：只要挂着公共节点中继，数据面仍然通，只是延迟升高。
        真正需要处理的是「没有任何中继」的情况（手机端强制中继配错节点）。
[·] 手机端「端口转发」填了就报 os error 99：该字段要求监听本机网卡，
        填对端地址必然失败，留空即可，已在界面上列为核对项。
