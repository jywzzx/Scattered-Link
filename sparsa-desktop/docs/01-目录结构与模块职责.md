# 目录结构与模块职责

> 命名约定：对外英文名 **Sparsa**，中文名 **零星**。不采用拼音写法。
> 协议标识 `network_name = lanlink` 保持不变 —— 它与 EasyTier 内核、已导入配置的手机端绑定，改了会让老配置全部失联。

## 一、仓库整体结构

前后端放在同一级目录，用 IDEA 打开仓库根目录即可同时看到两端：

```

│   ├── src/main/java/lanlink/
│   │   ├── Main.java               Swing 版入口（保留，与 --api 并存）
│   │   ├── core/                   与界面无关的核心能力
│   │   │   ├── Engine.java            EasyTier 内核进程管理、成员解析
│   │   │   ├── Invite.java            邀请码的生成 / 解析 / 归一化
│   │   │   ├── PhoneProfile.java      手机端配置模型与 TOML 生成

## 二、前端目录与模块职责

```
sparsa-desktop/
├── package.json            依赖、脚本、electron-builder 配置
├── vite.config.js          构建配置（base: './' 供 file:// 加载）
├── index.html              唯一 HTML 入口，含 CSP
│
├── electron/               主进程：有 Node 权限，绝不渲染界面
│   ├── main.cjs              窗口生命周期、单实例、菜单
│   ├── preload.cjs           contextBridge，只暴露白名单能力
│   ├── ipc.cjs               通道注册表（sparsa:<域>:<动作>）
│   ├── backend.cjs           拉起/停止 Java 后端，产出 {mode,baseUrl,token}
│   └── window-state.cjs      窗口位置记忆（含屏幕外兜底）
│
├── src/                    渲染进程：只有浏览器能力
│   ├── main.js               挂载 Vue、Element Plus、图标、路由

│   │   └── MainLayout.vue    侧栏 + 顶栏 + 状态栏
│   ├── views/                七个页面，与后端能力一一对应
│   │   ├── HomeView.vue          首页二选一 + 环境体检
│   │   ├── HostView.vue          创建房间（邀请码、成员、连通性）
│   │   ├── JoinView.vue          加入房间（邀请码/粘贴配置/IP+密码）
│   │   ├── PhoneView.vue         手机端配置（二维码、TOML、提示）
│   │   ├── DiagnosticsView.vue   网络诊断
│   │   ├── LogsView.vue          运行日志

│   ├── components/
│   │   ├── common/           CopyField / QrCanvas / TipList
│   │   └── room/             MemberTable / RelaySettings
│   ├── stores/               Pinia：app（环境）、session（会话）
│   ├── api/
│   │   ├── index.js            领域方法（页面只调这里）
│   │   ├── runtime.js          当前连真后端还是演示数据
│   │   ├── mock.js             演示模式的状态机
│   │   └── fixtures.js         与后端 DTO 对齐的假数据
│   ├── utils/                invite.js（邀请码/配置解析）、qr.js（容量模型）
│   └── styles/               设计令牌与 Element 变量覆盖

    ├── verify.mjs            无浏览器自检（解析逻辑 + 产物完整性 + 品牌一致性）

### 分层规则（照这个改不会乱）

| 层 | 允许做 | 禁止做 |
|---|---|---|
| `views` | 组装组件、调用 store / api、做局部交互状态 | 直接写 `axios`、直接读 `window.sparsa`、写业务算法 |
| `components` | 纯展示 + 事件上抛 | 发请求、改全局 store |
| `stores` | 持有跨页面状态、串联 api、实现轮询 | 直接操作 DOM、写样式 |
| `api` | 定义接口与错误归一化、mock/http 切换 | 写业务判断（例如「该不该给用户看红色告警」） |
| `utils` | 纯函数 | 有副作用（请求、定时器、DOM） |
| `electron` | 窗口、文件、剪贴板、进程 | 渲染界面、写业务逻辑 |

## 三、前后端边界

```
┌─────────────────────────────────────────┐
│ 渲染进程（Vue）                           │
│   views → stores → api                   │
│        ↘ utils（纯函数）                  │
└──────────────┬──────────────────────────┘
               │ HTTP + JSON（127.0.0.1，随机端口，X-Sparsa-Token）
┌──────────────┴──────────────────────────┐
│ 主进程（Electron）                        │
│   拉起/守护 Java 进程，把 {baseUrl, token} 交给渲染进程 │
└──────────────┬──────────────────────────┘
               │ 子进程
┌──────────────┴──────────────────────────┐
│ Java：lanlink.server.ApiServer           │
│   → lanlink.core（Engine / Invite / …）   │
│   → easytier-core.exe（虚拟网卡与隧道）    │
└─────────────────────────────────────────┘
```

为什么不让渲染进程直接起 Java 进程：渲染进程一旦拿到 Node 权限，页面里任何一处 XSS 都会变成任意命令执行。进程管理留在主进程，渲染进程只拿到一个 URL 和 token。

## 四、三处「刻意的不一致」

| 位置 | 现象 | 原因 |
|---|---|---|
| 配置文件名 `sparsa.toml` | 文件名是新品牌 | EasyTier 不校验文件名 |
| TOML 内 `network_name = "lanlink"` | 内容仍是旧标识 | 全端协议常量，改动即断连 |
| `docs/` 与 Java 包名 `lanlink` | 包名未改 | 重命名包会牵动全部构建脚本与测试，收益为零 |
