# 前后端接口契约

基址：`http://127.0.0.1:<port>/api/v1`（端口启动时随机分配并上报）
鉴权：请求头 `X-Sparsa-Token: <token>`，除 `/health` 外全部校验
编码：请求与响应均为 `application/json; charset=utf-8`
错误：非 2xx 时返回 `{"message": "给人看的中文原因"}`

## 一、系统

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 探活，免 token |
| GET | `/system/info` | 版本、系统、主机名、权限、内核路径 |
| GET | `/system/preflight` | 启动预检（聚合结果 + 5 项明细） |
| GET | `/system/network` | 局域网/公网 IP、NAT、端口映射（30 秒缓存） |
| GET | `/system/public-nodes?limit=3` | 社区公共节点探测与推荐 |
| POST | `/system/firewall` | 添加防火墙入站规则 |

`/system/preflight` 响应：

```json
{
  "ok": false,
  "title": "需要管理员权限",
  "detail": "创建虚拟网卡必须加载系统驱动，普通权限下无法完成。",
  "action": "请右键单击本程序，选择「以管理员身份运行」…",
  "items": [
    { "key": "core", "label": "内核文件", "ok": true, "detail": "已就位" }
  ]
}
```

## 二、会话

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/session` | 当前会话 + 内核实际参数 |
| POST | `/session/host` | 创建房间 |
| POST | `/session/join` | 加入房间 |
| DELETE | `/session` | 断开并停止内核 |
| POST | `/session/ping` | 与首个非本机成员做一次连通性测试 |
| POST | `/session/public-ip` | 重新探测公网 IP，判断邀请码是否失效 |

`POST /session/host` 请求体：

```json
{ "noP2p": false, "usePublicNodes": true, "relayUri": "tcp://节点:11010" }
```

`POST /session/join` 支持三种入参（择一）：

```json
{ "invite": { "host": "1.2.3.4", "port": 41273, "secret": "…" }, "noP2p": false }
{ "code": "1.2.3.4:41273#…" }
{ "host": "1.2.3.4", "secret": "…", "port": 41273 }
```

`/session` 响应（字段名与前端 `fixtures.js` 严格一致）：

```json
{
  "active": true,
  "role": "HOST",
  "myIp": "10.144.0.1",
  "listenPort": 32242,
  "invite": {
    "host": "223.104.202.74", "port": 32242, "secret": "gkykvnausmrwh8ku",
    "code": "223.104.202.74:32242#gkykvnausmrwh8ku",
    "displayHost": "223.104.202.74:32242", "roomName": "lanlink"
  },
  "relayUri": "", "noP2p": false, "usePublicNodes": false,
  "kernel": { "noP2p": false, "usePublicNodes": false, "relayUri": "", "peers": [] },
  "divergence": "",
  "startedAt": 1793161686217,
  "publicIp": "223.104.202.74"
}
```

> `kernel` 是**内核真正的命令行参数**，`noP2p` / `usePublicNodes` 是**界面声明**。
> 两者分开返回，是因为历史上出现过「界面显示强制中继、内核其实在直连」的假象。

## 四、手机端配置

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/phone/profile?mode=relay\|direct&relayUri=…` | 生成手机端配置 |
| POST | `/config/parse` | 解析粘贴进来的整段配置 |
| POST | `/invite/parse` | 解析邀请码 |

`/phone/profile` 响应有两种形态：

**未建房**（`ready: false`，不给半成品配置）：

```json
{ "ready": false, "mode": "direct", "toml": "", "carryText": "",
  "tips": [{ "level": "error", "text": "当前没有运行中的房间，配置无法生成。…" }] }
```

**正常**：

```json
{
  "ready": true,
  "mode": "relay",
  "toml": "ipv4 = \"10.144.0.9/24\"\n…",
  "carryText": "───── Sparsa 零星 配置 v1 ─────\n…",
  "tips": [{ "level": "error", "text": "…" }],
  "meta": {
    "networkName": "lanlink", "secret": "…",
    "initialPeer": "tcp://37.61.44.9:11010", "peerCount": 1,
    "lanIp": "10.63.97.158", "myIp": "10.144.0.9", "secondIp": "10.144.0.10"
  },
  "divergence": "【两端模式不一致】…",
  "ipCollisionHint": "虚拟 IPv4 由配置里的固定地址决定…"
}
```

`toml` 与 `carryText` 是**两个不同产物**，不可混用：

| 字段 | 用途 | 特征 |
|---|---|---|
| `toml` | 保存成文件给 EasyTier 导入 | 纯 TOML，零注释 |
| `carryText` | 二维码 / 微信文字搬运 | 带模式标记、操作步骤、`─── 配置开始/结束 ───` 分隔符，可反向解析 |

`POST /config/parse` 响应：

```json
{
  "ok": true, "mode": "relay",
  "toml": "…", "ipv4": "10.144.0.9", "relay": "tcp://37.61.44.9:11010",
  "secret": "…", "networkName": "lanlink",
  "problems": [],
  "invite": { "host": "37.61.44.9", "port": 11010, "displayHost": "37.61.44.9:11010" }
}
```

## 五、诊断

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/diagnostics` | 纯文本诊断块 |

文本里固定包含「界面声明」与「内核实际」两组，便于远程排查参数漂移。

## 六、状态码约定

| 码 | 含义 | 前端处理 |
|---|---|---|
| 200 | 成功 | — |
| 400 | 用户输入问题（邀请码非法、缺节点） | 直接展示 `message` |
| 401 | token 不匹配 | 提示重启后端 |
| 404 | 未知接口 | 属开发期错误 |
| 409 | 已有连接在运行 | 提示先断开 |
| 500 | 内核启动失败等 | 展示 `message`（已由 `Diagnostics.humanError` 转成中文） |

## 七、前端如何切换到真后端

`src/api/runtime.js` 判定顺序：

1. Electron 中运行 → 问主进程要 `{mode,baseUrl,token}`
2. 浏览器中运行且设置了 `VITE_API_BASE` → 直连该地址
3. 其余 → 演示模式（`src/api/mock.js`）

因此单独调后端不需要启动 Electron：

```bash
# 终端 A：起后端
java -cp "build/classes;lib/zxing-core-3.5.3.jar" lanlink.server.ApiMain --port 18080 --token dev

# 终端 B：起前端
set VITE_API_BASE=http://127.0.0.1:18080
set VITE_API_TOKEN=dev
npm run dev
```
