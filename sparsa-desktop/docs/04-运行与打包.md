# 运行、构建与自检

## 一、环境要求

| 组件 | 版本 | 位置 |
|---|---|---|
| Node.js | ≥ 22.12（Vite 7 要求） | 本项目实测 22.22.2 |
| JDK | 17 | 后端编译与运行 |
| 操作系统 | Windows 10/11 x64 | 虚拟网卡依赖 Wintun |

后端源码直接编译即可，无 Maven/Gradle 依赖；第三方库只有一个 `lib/zxing-core-3.5.3.jar`。

## 二、安装依赖

```bash
cd sparsa-desktop
npm install --registry=https://registry.npmmirror.com
```

> **npm 12 起默认拦截安装脚本**，Electron 的二进制不会被自动下载（表现为
> `node_modules/electron/dist` 不存在）。手动补一步：
>
> ```bash
> cd node_modules/electron
> set ELECTRON_MIRROR=https://registry.npmmirror.com/-/binary/electron/
> node install.js
> ```
>
> 若提示缓存目录无写权限，给 npm 指定项目内缓存：
> `npm install --cache ./.npm-cache`

## 三、编译后端

```bash
cd LANLink-v2

# 生成源文件清单（javac 对中文路径敏感，用参数文件最稳）
python -c "import os;print('\n'.join(os.path.join(dp,f).replace('\\','/') for dp,_,fs in os.walk('src/main/java') for f in fs if f.endswith('.java')))" > build/sources-main.txt

javac -encoding UTF-8 -cp "lib/zxing-core-3.5.3.jar" -d build/classes "@build/sources-main.txt"
```

完整打包仍走原有流水线：`build/build.ps1`（依赖 → 编译 → 静态检查 → 6 套测试 → 图标 → jpackage）。

## 四、三种运行方式

### 1）只调界面（不需要后端）

```bash
npm run dev          # 打开 http://localhost:5173
```

未检测到 Electron 桥与 `VITE_API_BASE` 时自动进入**演示模式**（`src/api/mock.js`），
所有页面可用，数据是内置的；侧栏底部会显示「演示模式」，状态栏有黄色标记。

### 2）前端连真后端（浏览器调后端）

```bash
# A：起后端（--port 0 让系统分配，日志里会打印实际端口与 token）
java -Dfile.encoding=UTF-8 -cp "LANLink-v2/build/classes;LANLink-v2/lib/zxing-core-3.5.3.jar" `
  lanlink.server.ApiMain --port 18080 --token dev

# B：起前端
set VITE_API_BASE=http://127.0.0.1:18080
set VITE_API_TOKEN=dev
npm run dev
```

### 3）完整桌面端（推荐）

```bash
npm run app:dev      # 同时起 Vite 与 Electron
# 或
npm run build && npm run app:start
```

Electron 主进程会自动寻找后端，优先级：
`SPARSA_BACKEND` 环境变量 → 打包产物 `Sparsa.exe --api` → 源码 `build/classes` 里的 `ApiMain` → 都没有则演示模式。

后端就绪信号（主进程据此判定可用）：

```
SPARSA_API_PORT=52311
SPARSA_API_TOKEN=xxxxxxxx
SPARSA_API_READY=1
```

## 五、自检

```bash
npm run verify       # 51 项：解析逻辑 + 产物完整性 + 品牌一致性（无需浏览器）
npm run build        # 编译 7 个路由 + 4 个公共组件
node_modules/electron/dist/electron.exe scripts/smoke.cjs   # 需桌面会话
```

后端侧（Java）：

```bash
# 2188 项逻辑自检
java -cp "build/test-classes;build/classes;lib/zxing-core-3.5.3.jar" lanlink.Tests

# 接口连通性
curl -H "X-Sparsa-Token: dev" http://127.0.0.1:18080/api/v1/system/info
```

## 六、打包

```bash
npm run app:dist     # electron-builder → release/
```

产物默认 portable 单文件。若要带后端一起发，需先把 Java 侧 `jpackage` 的 app-image
放到 `LANLink-v2/dist/LANLink/`，然后在 `package.json` 的 `build.extraResources`
里加上 `{"from":"../LANLink-v2/dist/LANLink","to":"backend"}`。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `electron/dist` 不存在 | npm 12 拦了 postinstall | 见第二节手动执行 `install.js` |
| 界面显示「演示模式」 | 没找到后端或后端启动失败 | 设置页看「后端探测」，点「重启后端」 |
| 点创建房间提示需要管理员权限 | 虚拟网卡要提权 | 以管理员身份运行 |
| 创建房间后立刻变「未连接」 | 内核启动即退出（多为权限/杀软） | 接口会返回具体原因，见「运行日志」 |
| 打包后白屏 | `base` 不是 `./` | 检查 `vite.config.js` 的 `base` |
| 沙箱/无桌面环境跑 smoke 被终止 | GUI 进程需要桌面会话 | 在普通桌面环境执行 |
