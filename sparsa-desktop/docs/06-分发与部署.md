# 分发与部署

目标：对方拿到一个压缩包，解压后双击 `Sparsa.exe` 就能用。
**不需要装 Java、Node.js、VC++ 运行库，也不需要自己启动任何服务。**

## 一、产物

```
sparsa-desktop/release/Sparsa-1.0.0-win64.zip
```

解压后是一个目录，结构与用途：

```
Sparsa-1.0.0-win64/
├── Sparsa.exe                     ← 让对方双击这个
├── 1-先看这里.txt                 ← 给非技术用户的图文说明
├── LICENSE-EasyTier.txt           ← 第三方组件授权
├── locales/                        Electron 语言包（不可删）
├── *.dll  *.pak  *.bin  *.dat      Electron 运行时（不可删、不可改名）
└── resources/
    ├── app/                        界面本体
    │   ├── package.json
    │   ├── dist/                   前端构建产物（index.html + assets）
    │   └── electron/               主进程脚本（窗口、IPC、后端守护）
    └── backend/                    本地服务（自带 JRE，对方无需装 Java）
        ├── SparsaBackend.exe
        ├── app/sparsa-server.jar
        ├── runtime/                裁剪后的 JRE
        └── engine/                 EasyTier 内核与驱动
            ├── easytier-core.exe
            ├── easytier-cli.exe
            ├── wintun.dll          虚拟网卡驱动
            ├── Packet.dll          WinDivert（可选功能用）
            └── WinDivert64.sys     WinDivert（可选功能用）
```

`Sparsa.exe` 启动后会在几百毫秒内自己拉起 `SparsaBackend.exe`，
读取它输出的端口与 token，再让界面连上去。用户不需要看到、也不需要手动启动它。

## 二、分发时必须一起带上的文件

漏掉任何一个都会导致「双击没反应」或「界面白屏」，**整个目录必须完整分发**：

| 文件 | 缺失后的现象 |
|---|---|
| `Sparsa.exe` | 无入口 |
| `resources/app/dist/**` | 窗口能开但白屏 |
| `resources/app/electron/**` | 窗口不出现 / 直接退出 |
| `resources/backend/**`（含 `runtime/`） | 界面能开，但一直显示「演示模式」，创建房间失败 |
| `resources/backend/engine/easytier-core.exe` | 建房/加入时报「未找到内核文件」 |
| `resources/backend/engine/wintun.dll` | 内核启动即退出：`Failed to create adapter` |
| `locales/`、`*.pak`、`*.dll` | Chromium 起不来或界面乱码 |

体积参考：解压后约 430 MB，压缩包约 150–170 MB。
其中 Electron 运行时 ~324 MB、后端（含 JRE 与内核）~99 MB。

> 分发时建议附一个 `.sha256` 文件，对方解压前可校验完整性，能挡掉「下载中断」这类假故障。

## 三、最低系统条件

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10 1809 及以上 / Windows 11 | 需要 Wintun 驱动支持；不支持 Win7/8 |
| 架构 | x64 | ARM64 需单独出包 |
| 内存 | 4 GB（建议 8 GB） | Electron ~200 MB + 后端 ~120 MB |
| 磁盘 | 500 MB 可用空间 | 解压后约 430 MB |
| 权限 | **管理员权限**（运行时提权） | 加载虚拟网卡驱动必需，UAC 弹窗选「是」 |
| 网络 | 能出网（UDP + TCP） | 直连失败时要经社区公共节点中继 |
| 端口 | 20000–60000 中任选一个可用 | 每次建房随机选取，不在固定端口暴露 |
| 运行库 | **无需额外安装** | Electron 静态链接 C 运行时；JRE 随包分发 |

不需要：Java、Node.js、Visual C++ Redistributable、.NET、Python。

## 四、常见的缺失依赖与路径问题

### 1. 直接在压缩包里双击

**现象**：提示找不到文件、或界面白屏。
**原因**：Electron 与后端都需要从磁盘读取大量同级文件，压缩包内的虚拟路径不成立。
**处理**：先「全部解压」到硬盘再运行。说明文件里已写在第一条。

### 2. 安全软件隔离 `wintun.dll`

**现象**：创建房间时内核立刻退出，日志出现 `Failed to create adapter`。
**原因**：虚拟网卡驱动是最常被误杀的文件之一。
**处理**：把整个文件夹加入白名单后重新解压；若文件已被隔离，需要重新解压一次。

### 3. 缺少 `easytier-core.exe`

**现象**：提示「未找到内核文件 easytier-core.exe（应位于 engine 目录下）」。
**原因**：解压不完整，或杀软删了 exe。
**处理**：重新解压；核对 `resources\backend\engine\` 下应有 5 个文件。

### 4. 路径含中文或空格

**已验证**：本包在含中文的路径下（`D:\局域网联机软件\...`）可正常运行。
但仍有两点注意：

- 路径总长度不要超过 200 字符（Windows 260 上限，Electron 解压后层级较深）；
- 不要放在 `C:\Program Files\` 下运行绿色版，UAC 与只读权限会导致窗口位置、日志写入失败。
  建议放 `D:\Sparsa\` 这类普通目录。

### 5. 没有管理员权限

**现象**：界面能开，点「创建房间」后立刻变回「未连接」，提示里带「未以管理员身份运行」。
**原因**：虚拟网卡要加载系统驱动（Wintun），普通权限装不了。
**处理**：右键 `Sparsa.exe` → 以管理员身份运行；或在文件属性里勾选「以管理员身份运行此程序」。

### 6. 端口被占用 / 防火墙拦截

**现象**：建房成功但对方连不上；或本机能连、别人进不来。
**处理**：
- 端口是随机选的，冲突概率低；真冲突时重新建房即可换端口；
- 若被防火墙拦，在「网络诊断」页点「添加防火墙入站规则」；
- 公司网络/校园网常禁用 UDP，此时改用「强制统一中继」并把两端填同一个节点。

### 7. 界面显示「演示模式」

**现象**：侧栏底部显示「演示模式」，所有操作都像成功了但成员永远是假的。
**原因**：主进程没能拉起后端（后端文件缺失、被杀软拦住、或启动即崩溃）。
**处理**：进「设置 → 后端连接」看「后端探测」里列出的可执行文件路径；
点「重启后端」重试；仍失败则看 `%LOCALAPPDATA%\LANLink\logs` 下的内核日志。

### 8. 换机器后窗口跑到屏幕外

**现象**：启动后看不到窗口。
**原因**：窗口位置记忆存在 `%APPDATA%\Sparsa\window-state.json`，跨显示器时会失效。
**处理**：删掉该文件重启（程序本身也会把越界位置收敛回主屏，属双保险）。

## 五、首次运行会遇到的两道系统提示

1. **UAC 提权**：双击 `Sparsa.exe` 会弹「是否允许此应用对你的设备进行更改」，必须选「是」。
   选「否」时程序仍能打开，但创建房间会失败，诊断页会显示「需要管理员权限」。
2. **SmartScreen**：未签名程序在他人电脑上可能提示「Windows 已保护你的电脑」。
   让对方点「更多信息」→「仍要运行」。这不是程序损坏，是没有代码签名证书。

## 六、数据落地位置

| 内容 | 路径 |
|---|---|
| 窗口位置 | `%APPDATA%\Sparsa\window-state.json` |
| 内核日志 | `%LOCALAPPDATA%\LANLink\logs\engine-*.log` |
| 启动日志 | `%LOCALAPPDATA%\LANLink\startup.log` |

卸载：删除整个目录即可。虚拟网卡适配器会在退出时自动卸载；
若残留，可在「设备管理器 → 网络适配器」删除名为 `wintun` 的项。

## 七、重新打包

```bash
cd sparsa-desktop
npm run build            # 先产出 dist/
node build/package.mjs   # 编译后端 → jpackage → 组装 → 压缩
```

脚本会用 `JAVA_HOME`（默认 `E:\develop\jdk\jdk-17`）里的 `javac / jar / jpackage`。
打包完成后 `release/Sparsa-<版本>-win64.zip` 即为可分发包。

已知的两个陷阱（脚本里已规避，改脚本时别踩回去）：

1. `javac @sources.txt` 参数文件按系统 ANSI 读取，中文路径会 `MalformedInputException`
   → 改为把源文件直接作为命令行参数传；
2. Windows PowerShell 5.1 按 ANSI 读取 `.ps1`，脚本里写中文路径会乱码并报
   `DirectoryNotFoundException` → 压缩脚本保持纯 ASCII，路径走命令行参数。
