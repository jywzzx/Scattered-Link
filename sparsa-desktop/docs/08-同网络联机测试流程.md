# 同网络联机测试流程

适用场景：电脑与手机连接同一台路由器（同一 Wi-Fi 或同一交换机的有线网络）。
目标：验证「建房 → 导出配置 → 手机导入 → 双方互见 → 可 ping 通 → 游戏内可见」这条链路。

每个步骤都给出**通过判据**。某一步不满足，先在「失败排查」里按现象定位，不要继续往下走。

## 0. 前置条件

| 项 | 要求 | 如何确认 |
|---|---|---|
| 网络拓扑 | 电脑与手机连同一台路由器 | 手机 Wi-Fi 详情里的网关，与电脑 `ipconfig` 里的默认网关相同 |
| 路由器隔离 | 关闭「AP 隔离 / 客户端隔离」 | 路由器后台的无线设置里查该项名称，关闭后重启无线 |
| 电脑权限 | 以管理员身份运行 | 首页「本机环境」中「管理员权限」显示「已提权」 |
| 内核文件 | `engine` 目录完整 | 首页「本机环境」中「内核文件」显示「就位」 |
| 其它 VPN | 退出 Clash、Radmin、ZeroTier 等 | 任务栏与网络适配器列表里均无 |
| 手机端 | 已安装 EasyTier 官方 App | 应用列表可见，版本 2.6.x |

说明：同一台路由器下不需要开启「强制统一中继」。该模式会让流量绕经公网节点，延迟高于局域网直连。

## 1. 清理上一轮残留

1. 电脑端：若界面顶部有「断开连接」按钮，先点击断开。
2. 手机端：进入 EasyTier，删除此前导入的配置（避免继续使用旧密钥或旧节点）。
3. 手机端：关闭 EasyTier 中正在运行的连接。

通过判据：电脑端状态显示「未连接」；手机端配置列表为空，且没有活动连接。

## 2. 启动电脑端

源码方式（开发自测）：

```
cd sparsa-desktop
npm run app:dev
```

打包方式（分发前验收）：解压后双击 `Sparsa.exe`，UAC 提示选择「是」。

通过判据：窗口出现且不白屏；左侧导航 7 项可点击；窗口底部不显示「演示模式」。
若显示「演示模式」，说明后端未启动，先到「设置 → 后端连接」点「重启后端」。

## 3. 电脑端环境自检

进入「网络诊断」页，检查以下四项。

| 检查项 | 通过判据 |
|---|---|
| 管理员权限 | 已提权 |
| 启动预检 | 「检查通过」或五项全部为绿色 |
| 局域网 IP | 有值，形如 `192.168.x.x` 或 `10.x.x.x`，与路由器网段一致 |
| 公网 IP | 有值（同网络测试不依赖它，但为空说明出网被拦） |

若「端口映射」显示「未生效」，同网络测试可不处理；异网测试才需要。

## 4. 创建房间

进入「创建房间」页。

1. 链路设置中，「强制统一中继」保持**关闭**。
2. 「社区公共节点」可关闭。同一路由器下走局域网地址即可，开启只增加备用路径。
3. 点击「创建房间」。

通过判据：页面切换为「房间已创建」，出现一行邀请码，形如 `192.168.1.24:41273#k7m2q9x3rt5vb6n`。
本机虚拟 IP 固定为 `10.144.0.1`。

注意：点击创建后，链路参数即被内核固定。之后再改动开关不会生效，必须断开重来。

## 5. 生成手机端配置

进入「手机端配置」页。

1. 配置模式选择「直连优先」。
2. 核对页面下方「导入前请核对」中列出的项目。
3. 点击「复制配置内容」；若手机与电脑同一账号可用微信发送，或点击「保存为文件」得到 `sparsa.toml`。

通过判据：二维码正常显示；配置文本中 `network_name` 为 `lanlink`；初始节点以本机局域网 IP 开头（`tcp://192.168.x.x:端口`）。
若顶部出现红色横幅提示两端模式不一致，说明建房时勾选项与当前配置模式不同，回到第 1 步重新建房。

## 6. 手机端导入配置

三种搬运方式任选一种，效果相同。

| 方式 | 操作 |
|---|---|
| 扫码 | 手机相机扫描电脑端二维码，全选复制文本 |
| 文本 | 微信发送配置文本到手机，用记事本新建文件，粘贴后保存为 `sparsa.toml` |
| 文件 | 把 `sparsa.toml` 传到手机存储，在 EasyTier 里导入 |

在 EasyTier 中点击「导入配置文件」，选择该文件。

导入后逐项核对：

| 项 | 应为 |
|---|---|
| 网络名称 | `lanlink` |
| 网络密钥 | 与电脑端邀请码中 `#` 之后的部分一致 |
| DHCP | 关闭 |
| 虚拟 IPv4 | `10.144.0.9/24` |
| 初始节点 | `tcp://电脑局域网IP:端口` |

通过判据：五项全部一致。任一项不符，删除配置后重新导入，不要手工改字段。

## 7. 手机端发起连接

1. 在 EasyTier 中选中该配置，点击启动。
2. 系统弹出 VPN 授权请求，选择「允许」。

通过判据：App 内显示已连接；通知栏出现 VPN 图标。

## 8. 电脑端确认成员

回到「创建房间」页，观察成员列表。列表每 2 秒自动刷新。

| 观察项 | 通过判据 |
|---|---|
| 成员数量 | 由 1 变为 2 |
| 新增成员的虚拟 IP | `10.144.0.9` |
| 链路列 | 显示「直连」 |
| 延迟列 | 通常小于 10 ms |
| 隧道列 | `udp` 或 `tcp` |

若链路列显示「中继」，说明点对点直连未建立，按「失败排查」第 3 条处理。

## 9. 双向连通性验证

电脑到手机：

1. 点击「测试连通性」。
2. 通过判据：提示「与 10.144.0.9 连通」，延迟为个位数毫秒。

手机到电脑：

1. 在手机浏览器访问 `http://10.144.0.1`，出现任何响应即说明路由可达。
   若电脑未开网页服务，改用支持 ping 的 App 执行 `ping 10.144.0.1`。
2. 通过判据：有响应，丢包率为 0。

说明：电脑端不测试 ping 自己。ping 本机走回环，无法证明虚拟网卡与隧道是否正常。

## 10. 游戏联机验证

1. 电脑端进入游戏，选择「局域网」模式创建房间。
2. 手机端进入同一游戏，在局域网列表中查找该房间；若无列表，直接填写主机地址 `10.144.0.1`。
3. 若游戏要求填写加入方地址，填写 `10.144.0.9`。

通过判据：双方出现在同一局，操作无明显延迟。同一路由器下延迟通常在 10 ms 以内。

注意：部分游戏只扫描本地网段广播，不识别虚拟网卡。此类游戏需在游戏内手动填写 IP，或在电脑端设置环境变量 `LANLINK_BROADCAST=1` 后重新建房。

## 11. 失败排查

按现象定位，不要同时改多个设置。

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| 电脑端点击创建房间后立刻变回「未连接」 | 未以管理员身份运行，虚拟网卡创建失败 | 关闭程序，右键「以管理员身份运行」后重试；查看「运行日志」中的失败原因 |
| 手机端显示已连接，电脑端成员列表始终为 1 | 两端密钥或网络名称不一致；或路由器开启了 AP 隔离 | 核对第 6 步五项；关闭路由器 AP 隔离后重试 |
| 成员列表出现 `10.144.0.9`，但链路显示「中继」 | 局域网地址不通，流量绕到社区节点 | 检查电脑防火墙是否放行该端口；确认手机与电脑真的在同一网段 |
| 成员可见，但「测试连通性」不通 | Windows 防火墙拦截 ICMP 或 UDP | 「网络诊断」页点「添加防火墙入站规则」后重试 |
| 手机端导入后报配置无效 | 文本被聊天软件改写，或标记行缺失 | 用「复制配置内容」重新搬运，不要手工编辑 TOML |
| 二维码扫不出来 | 屏幕缩放导致图像失真 | 用「复制配置内容」改用文本方式 |
| 换房间后手机仍连旧房间 | 手机端保留了旧配置 | 删除手机端全部配置，重新导入 |

## 12. 判定标准

以下五项同时满足，判定同网络联机通过：

1. 电脑端成员列表出现 `10.144.0.9`，链路为「直连」；
2. 电脑端「测试连通性」返回连通，延迟小于 20 ms；
3. 手机端可访问 `10.144.0.1`；
4. 双方在同一游戏中互相可见；
5. 全程无「模式不一致」红色提示。

## 13. 记录与反馈

测试失败时导出以下内容，便于定位：

- 「网络诊断」页 → 「复制诊断信息」（含界面声明与内核实际参数两组）；
- 「运行日志」页截图；
- `%LOCALAPPDATA%\LANLink\logs\engine-*.log` 文件；
- 手机端 EasyTier 的日志页截图。
